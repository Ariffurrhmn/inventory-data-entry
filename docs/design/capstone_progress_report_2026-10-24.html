1. Current position

A working local document-processing prototype is built. It can classify printed documents, recover some tables automatically, accept structured extraction JSON, verify evidence and arithmetic, and persist submissions.

The main unfinished boundary is unattended extraction: current LLM extraction experiments use isolated Codex agents and a manual handoff. A standalone application cannot call these agents as its extraction backend. Independent human field references are also still missing.

Project scope

Automated Inventory Data Entry through Intelligent Character and Document Structure Recognition is a document-digitization gateway for an external inventory/ERP consumer. Current inputs are English printed, typeset or thermal documents, including photographs. Classes: purchase_order, receipt, delivery_note, customer_copy.

Handwritten transaction fields, stock management, product matching, valuation and an owned ERP ledger are outside the current scope. Cloud deployment and phone-to-server capture remain future integration work.

These are saved classifier measurements from earlier work; they are not independent final accuracy and were not rerun to create this report. The latest downstream work did not change the selected model.

4. What remains and what blocks it

Unattended extraction backend

The inspected machine has an i7-1265U (10 cores / 12 logical processors), about 16 GiB RAM, Iris Xe graphics and CPU-only PyTorch. Only about 1.2–1.4 GiB physical RAM was free during inspection.

Ollama/llama.cpp commands were absent from PATH. The inspected Gemma cache contained configuration only. An actual offline load failed for missing weights after 58.120 seconds, including import/load overhead. No generation was executed or model downloaded.

Blocker: a provisioned callable runtime/model and sufficient free memory. CPU inference may be possible after provisioning, but model peak memory, generation latency, schema compliance and extraction accuracy remain unmeasured.

General localization and reliable truth

Three tested layouts have no accepted grid. Borderless tables, merged cells, substantial perspective distortion and large rotations are not established by the current ruled-grid detector.

Independent human field references and a separately collected real holdout are still missing. Existing exposed development examples have been reused adaptively; they cannot establish final generalization.

Blocker: broader layout methods plus human-reviewed, source-grouped evaluation data. No historical test inputs should be opened to tune these methods.

Further application work

  • Connect an unattended extractor and preserve source evidence, failure/retry behavior and schema validation.
  • Resolve numeric separator policies and ambiguous row associations without silently rewriting OCR.
  • Integrate actual phone-to-server capture and a real consumer API if required for the final demonstration.
  • Prepare deployment, authorization, retention and load testing for any production-facing system.
  • Align final report, slides and demo claims with printed-only scope, the local hybrid classifier and measured limits.

5. How reliable field evaluation will work

  1. Create source-bound blank forms. Five actual candidate records already have blank forms; they do not copy candidate values or source row counts into reference answers.
  2. Human transcription first. A reviewer reads the image before seeing AI suggestions, records identity and transcribes each header, total and item-description/numeric field.
  3. Record uncertainty honestly. Distinguish readable values, genuinely absent fields, unreadable printing, uncertain interpretation and unreviewed fields. Missing amounts do not become zero.
  4. Account for every row. Align source rows one-to-one with candidate rows; record missing source rows and spurious candidate rows. Mark incomplete reviews explicitly.
  5. Append and score. Save a separate immutable revision. Accuracy is available only for declared independent human-verified references; AI reviews cannot assert human verification.
MeasureDefinition
Field accuracyCorrect / eligible reviewed fields. Exact text equality; exact Decimal equality for numeric strings. Report readable-value and absent-field strata separately.
Prediction coverageNon-null candidate fields / eligible fields. Population rate only; it does not measure correctness.
Row precision / recallMatched / candidate rows and matched / source rows, only for complete row review. Empty denominators stay undefined.
Excluded contentCount uncertain, not-legible and unreviewed fields separately. Publish missing/spurious rows alongside field scores.

Report results by document type and field name, with per-document findings and micro totals. Multiple extraction variants on the same documents are not independent samples. This offline workflow is separate from the annotation portal and from any internal ERP approval process.

7. How to run the built components

Use PowerShell from the project root. The configured interpreter and Tesseract must remain available. These commands are instructions; report creation did not restart the apps or rerun experiments.

# Supervisor classifier demonstration
.\classifier\Open Demo.cmd
# http://127.0.0.1:8770

# Downstream gateway, with automatic region OCR enabled
.\services\document_pipeline\start.ps1 -RegionOcr
# http://127.0.0.1:8772 — use a NEW submission key

# Configured Python and downstream checks
$py = (Get-Content classifier/engine/runtime.local.json | ConvertFrom-Json).python
& $py -m unittest discover -s services/document_pipeline -p 'test_*.py'

# Localize a permitted image into a NEW audit directory
& $py services/document_pipeline/run_localization.py IMAGE --output NEW_DIRECTORY

# Separate human field review: see FIELD_REVIEW.md for the complete procedure
& $py services/document_pipeline/field_review.py prepare --image IMAGE --candidate RECORD_JSON --output NEW_BLANK_JSON

Default Open Pipeline.cmd remains primary-OCR-only. Region mode preserves classifier OCR and stores separate exact extraction evidence and derived audits. Extraction still requires exported prompt → external agent response → JSON import. Existing idempotency keys replay saved results.

Gateway records live in services/document_pipeline/.runtime/submissions.sqlite3; region audits live beside the chosen database under regions/. Future field reviews use a separate field_reviews.sqlite3. Report files and AI candidates never automatically enter training or canonical annotation truth.
