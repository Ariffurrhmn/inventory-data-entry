# Independent field review and evaluation

`field_review.py` is a separate offline workflow. It never edits extraction JSON, classifier data, annotation editions, or the existing annotation review database. No field ground truth has been created by this implementation. AI drafts remain `reviewer_type=ai`, `human_verified=false`. The tests contain controlled synthetic fixtures and measure software behavior only.

Use the configured classifier Python in the following commands, from the project root. Replace the paths with a permitted development image and a **single extraction record**, not a multi-record response wrapper. Use a new output name; exports refuse replacement.

```powershell
python services/document_pipeline/field_review.py prepare --image <image> --candidate <record.json> --output <blank-review.json>
python services/document_pipeline/field_review.py append --image <image> --candidate <record.json> --review <review.json> --database services/document_pipeline/.runtime/field_reviews.sqlite3
python services/document_pipeline/field_review.py evaluate --image <image> --candidate <record.json> --review <review.json> --output <metrics.json>
python -m unittest discover -s services/document_pipeline -p test_field_review.py
```

The template contains exact SHA-256 identities for the image bytes and extraction-file bytes. Any change, including JSON serialization, requires a new binding. Keep image, candidate and saved review together. Review revisions append UUID/timestamp/hash records in the separate SQLite database; update/delete triggers preserve earlier entries through this API. SQLite is not an authentication or tamper-proof audit system; a filesystem owner can modify it. Reviewer identity and independent-review attestations are declarations, not machine-verifiable identity proofs. AI agents must never select a human role or assert these declarations.

## Human procedure

1. A human transcribes the image **before looking at the candidate or AI suggestions**. The blank form deliberately copies no candidate values or row count. Enter an identity, set `reviewer_type=human`, and record an image-based judgment for each header, total and row field.
2. Each field has `status`, `value`, and optional `note`. Use `value` with the exact printed string (plain decimal strings for numeric fields); `absent` for a genuinely nonexistent field; `not_legible` for visible unreadable printing; `uncertain` for unresolved interpretation/locale; or `unreviewed`. All statuses except `value` require null. Missing subtotal/tax/discount never becomes zero. Note numeric normalization explicitly; do not infer a decimal separator from arithmetic. `raw_text` means the printed item-description cell, not a synthesized line including numbers. Dates remain source strings. Incidental handwriting stays outside the printed-only scope.
3. Add **every source item row**, including rows missing from the candidate, as `{"candidate_index": null, "fields": {"raw_text": {...}, "quantity": {...}, "unit_price": {...}, "line_total": {...}}`. After transcription, inspect the candidate and align each source row to its zero-based candidate index. Leave unmatched source rows null; list unmatched candidate indices in `spurious_candidate_rows`. Duplicate alignments are rejected. When every candidate/source row has been considered, set `rows_complete=true`; all candidate rows must then be accounted for. An unresolved row alignment should remain incomplete rather than guessed.
4. Set `human_verified=true` only after actual human image review. Set `independent_reference=true` and `reference_first_attestation=true` only if the image-first procedure occurred. If a human saw AI output first, retain the useful assisted review, but leave `independent_reference=false`; it is ineligible for this accuracy report. Resolve disagreements with another independent human before adopting a reference; preserve all earlier revisions.
5. Append the review and run evaluation. Revisions require new append entries. An AI can prepare blanks and propose separate corrections; it cannot provide independent human truth. No automated promotion into canonical annotations exists.

## Metric definitions and limits

Only verified, independent human references are accepted. `field_accuracy` is correct / eligible reviewed fields; exact string equality is used for textual fields and exact Decimal equality for nonnegative plain numeric strings (`2` equals `2.00`, with no tolerance, locale guessing or arithmetic repair). `absent` is scored as null and is included in the denominator. Therefore absent-heavy documents can inflate aggregate accuracy: always publish findings and stratify by document type, field name and value-versus-absent status. Numeric source normalization belongs in human notes. Text case/spacing changes count as errors. A missing row contributes null predictions for all its reviewed fields. Missing and spurious row counts are reported separately; a candidate with extra rows can have high matched-field accuracy, so never report field accuracy alone.

`prediction_coverage` is non-null candidate values / eligible fields, including reviewed absent fields; it is a population rate, not a correctness estimate or confidence. Uncertain, not-legible and unreviewed fields have separate counts and are excluded from accuracy. Incomplete row reviews are explicitly marked; row recall/precision must only be computed across `rows_complete=true` reviews: matched / source rows and matched / candidate rows, respectively, where matched = source rows minus missing rows. Empty denominators are undefined, never 100%. Summed field counts support micro accuracy; report per-document results as well and count excluded documents. Do not treat several extractor variants on the same images as independent samples.

Schema validity, literal OCR support, arithmetic consistency, human field accuracy, row recovery and runtime are distinct measurements. This command only measures field agreement against declared independent human truth. It does not invoke the contract verifier or turn arithmetic into truth. Existing exposed development images remain development evidence; reliable final evaluation still needs a separately collected, independently reviewed source-grouped holdout. Historical test inputs are not needed or authorized by this workflow.

The saved downstream follow-up agents sometimes used full row strings in `raw_text`. Those historical responses are preserved and are not validated description transcriptions. The current prompt/schema description now explicitly restricts `raw_text` to the item-description cell. Schema string validity alone cannot enforce that semantic rule. Human scoring against the description cell will count whole-row strings as mismatches; report this contract limitation when comparing the saved trials.
